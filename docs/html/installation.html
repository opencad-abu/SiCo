01 / GET STARTED

安装与首次启动

普通用户选择 CAD 已部署的完整安装，再加载项目环境。安装根、Python 和 Virtuoso 初始化入口需要成套使用。

准备运行环境

组件何时需要要求
Linux x86_64全部功能使用经站点确认的平台组合。当前运行包已有 EL7 / EL8 及当前 EL9 主机验收记录，具体资格以所选包为准。
Cadence Virtuoso / OpenAccessOA 输入、菜单、MTS、文本 view站点提供工具和许可证；context 必须匹配发行验证的 Cadence 版本，当前验证基于 IC23.1。
Python / QtSiCo 与图形工具二进制安装使用 runtime/python/；源码测试使用配置好依赖的站点 Python。当前 Assistant 要求 Python 3.9.13。
X11 与系统图形库GUI有效的 DISPLAY 与 X11 授权。LSF 节点中文输入还需 IBus/libpinyin、D-Bus 和 Qt IBus plugin。
Calibre / Quantus / StarRC / Abstract对应 CAD flow按使用范围配置 PATH、许可证和 PDK 规则；SiCo 安装不代替这些 EDA 工具。
LSF / Environment Modules集群运行 / MTS 项目选择LSF 按需启用；MTS 项目选择要求可用的 modulecmd 与明确的 modulefiles 目录。

部署完整运行包

如果站点已有 SiCo，请直接进入下一节。首次部署时，由 CAD 将已验收的运行包解压到一个新的版本目录，保留原版本以便切换。

  1. 取得同一版本的归档及其 SHA-256 校验文件，先校验，再查看归档顶层目录。
  2. 解压到新的空目录，确认 bin/、tools/、runtime/python/、etc/config/sico-install.json 和 RUNTIME-MANIFEST.json 齐全。
  3. 将 SICO_HOME 指向包含上述目录的实际安装根；如果归档自带顶层目录，要指向该顶层目录内部。
  4. 按下面的检查启动新进程。安装更新时先核对 CAD 已维护的 etc/flow-defaults/，将站点修改合并到新版本。
Bash · 部署示意，替换文件名和新目录
sha256sum -c /path/to/sico-release.tar.gz.sha256
tar -tzf /path/to/sico-release.tar.gz
mkdir /path/to/new-sico-install
tar -xzf /path/to/sico-release.tar.gz -C /path/to/new-sico-install

校验文件若使用相对文件名，应在归档所在目录执行校验。运行包已带 Python，不需要向系统 Python 安装 SiCo；站点的 EDA、许可证、图形与调度器环境仍需单独就绪。

配置启动 shell

以下示例使用二进制安装 /software/sico/latest-bin。先加载站点项目 setup，再执行这些设置；将安装路径替换为实际位置。

Bash · 二进制安装
source /path/to/project/setup.bashrc
export SICO_HOME="/software/sico/latest-bin"
export SICO_PYTHON_ROOT="$SICO_HOME/runtime/python"
export SICO_PYTHON="$SICO_PYTHON_ROOT/bin/python3"
export SICO_SYSTEM_LD_LIBRARY_PATH="$SICO_PYTHON_ROOT/lib:$SICO_HOME/lib"
export SICO_AI_PYTHON_LIBRARY_PATH="$SICO_SYSTEM_LD_LIBRARY_PATH"
export SICO_RUNTIME_TOOLS="$SICO_HOME/tools"
export LD_LIBRARY_PATH="$SICO_HOME/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export PATH="$SICO_HOME/bin:$PATH"
unset SICO_AI_PYQT_ROOT SICO_AI_QTERMWIDGET_RUNTIME
unset SICO_AI_RELEASE_ROOT SICO_AI_CONTEXT SICO_AI_QT_PLUGIN_PATH
Csh / Tcsh 的等价配置
Csh · 先加载站点项目环境
source /path/to/project/setup.cshrc
setenv SICO_HOME "/software/sico/latest-bin"
setenv SICO_PYTHON_ROOT "$SICO_HOME/runtime/python"
setenv SICO_PYTHON "$SICO_PYTHON_ROOT/bin/python3"
setenv SICO_SYSTEM_LD_LIBRARY_PATH "$SICO_PYTHON_ROOT/lib:$SICO_HOME/lib"
setenv SICO_AI_PYTHON_LIBRARY_PATH "$SICO_SYSTEM_LD_LIBRARY_PATH"
setenv SICO_RUNTIME_TOOLS "$SICO_HOME/tools"
if ( $?LD_LIBRARY_PATH ) then
    setenv LD_LIBRARY_PATH "$SICO_HOME/lib:$LD_LIBRARY_PATH"
else
    setenv LD_LIBRARY_PATH "$SICO_HOME/lib"
endif
setenv PATH "$SICO_HOME/bin:$PATH"
unsetenv SICO_AI_PYQT_ROOT
unsetenv SICO_AI_QTERMWIDGET_RUNTIME
unsetenv SICO_AI_RELEASE_ROOT
unsetenv SICO_AI_CONTEXT
unsetenv SICO_AI_QT_PLUGIN_PATH
Python/Qt 动态库通过 SICO_SYSTEM_LD_LIBRARY_PATH 传给 SiCo 子进程。不要把整套 Python/Qt 库直接前置到 Virtuoso 的 LD_LIBRARY_PATH。上面加入全局路径的仅是安装的 lib/ 兼容库目录。

进入个人工程并检查安装

Bash · 首次检查
cd /path/to/my/project
test -f "$SICO_HOME/etc/config/sico-install.json"
test -x "$SICO_PYTHON"
command -v sico virtuoso
"$SICO_PYTHON" -I -B -c 'import sys; print(sys.version)'
sico --help
drc --help
lvs --help
rce --help
mts-netlistor --help

共享安装时，每个用户在自己的工程工作目录启动。通常保持 SICO_TEMP_DIR 未设置，SiCo 自动使用 <启动目录>/.sico。若旧环境指定了错误的状态根，可在启动前清除 SICO_TEMP_DIR 和已退出的 CAD_TEMP_DIR。不要删除已有会话目录来解决配置错误。

启动与模型配置

执行 sico 打开独立首页，启动或复用当前工程服务。它不会自动启动 Virtuoso。要在 Virtuoso 内使用菜单，请继续配置 .cdsinit。

Bash · 需要 AI 功能时，在工程服务启动前设置
export SICO_BACKEND="codex"
export SICO_PROVIDER="responses"
export SICO_API_BASE_URL="https://api.example.com/v1"
export SICO_MODEL="your-model-name"
# SICO_API_KEY 由站点的私有凭据配置注入。
sico

模型地址与模型名配套设置。现行 Codex 后端要求上游提供 Responses 接口；仅提供 Chat Completions 的地址不能直接用于此配置。旧 SICO_API_URL 暂可读取，但与新地址冲突会报错。模型可选值由站点服务提供，SiCo 不设固定模型默认值。

源码测试安装

站点指定源码测试时，选择 /software/sico/latest，将 SICO_PYTHON_ROOT 改为站点 Python 3.9.13 目录，并设置 SICO_AI_PYQT_ROOT="$SICO_HOME/tools/ai/terminal/pyqt"。其余共享变量保持同一安装。源码测试树还需站点准备匹配的 worker context 和 Qt 终端依赖。

源码树通过 scripts/sicoAutoLoad.il 接入；二进制安装通过 sicoBoot.cxt 接入。后者缺失时应修复安装，不能用另一份源码树的文件补齐。

更新、切换与排错

  1. 结束或核对现有任务，关闭 SiCo 窗口，正常停止工程服务。
  2. 关闭旧 Virtuoso，在新 shell 加载目标版本环境。单纯修改 shell 变量不会更新已经运行的服务。
  3. 使用同一套安装入口重新启动，检查版本与连接。回退时成套切换到保留的旧安装。
Bash · 正常停止当前工程服务
sico service-stop --project-dir /path/to/my/project

若仍有活动或待核对任务，停止可能被拒绝；先处理这些任务。出现 SICO_HOME conflicts 时检查 command -v sico 与 SICO_HOME 是否属于同一安装；出现旧变量迁移错误时按迁移表修改启动脚本。
