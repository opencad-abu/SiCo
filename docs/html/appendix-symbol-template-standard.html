1. 已有能力与本草案的范围

Symbol 数据和创建流程已经存在，不能以本草案尚未发布推论它们不存在：

  • Symbol v1定义持久模板、目标 schematic、 显式端口映射和 preview/create/inspect 生命周期。
  • 轮廓重绘定义 template_outline、 draw_symbol、供电位置、端口短线和固定标签；原矩形路径继续兼容。
  • 内容附录 B.9已有 symbol.json； symbol_checks.py校验接口、锚点、 图元、总线和资格回执。

当前执行边界（三审补充）： ctpl_ 的 preview/create/draw 经 TemplateCatalog.locate → replay.engine_record 取得 transient raw record； template_outline 目前读取 record["assets"]["symbol"]，不是直接读取 B.9 的 symbol.json。因此 symbol.json 目前是持久源事实/资格权威，不是完整的 renderer 输入；修改一个 symbol.json 字段不能推定创建结果随之改变。当前路径要求 detail_level=raw 且有 retained private capture，L1/L2/L3 投影只能作为离线参考，不能据此 宣称可创建。要统一到 B.9 单一路径，须先补齐 pin figure、lpp、line width 等信息并让 reader/renderer 消费该文档；在此之前按本边界记录证据。

本草案保留“区分必须满足和可适配内容”的思路，但不能让 LLM 凭理由改变既有硬约束。 当前失败根因应通过固定模板、请求、预览、保存回读和原生截图定位。本次未取得原审计所称 “效果差”的具体失败件，不能认定它由缺少约束层级或提示词造成。

范围是设计单元 Symbol 的数据参考与消费，不重定义 PDK 器件 symbol/CDF，不生成或修改 PDK 库。层次/PCell Symbol、多 pin terminal 和复杂 bus 表达式须沿用现有拒绝边界。 数据采集可完整保留未支持事实；保存了事实不等于当前 renderer 能创建。

2. 一份事实的唯一归属

不采用原稿的 sico.symbol.template.v1 与 .minimal 双格式，不把端口、约束、几何和 允许操作在多个对象里各写一份。最小可用数据是现有格式的完整必备部分，不能删掉单位、 来源、接口映射或能力证据后另称“最小版”。

symbol.json 必备公共信封以及 frame,terminals,anchors,outline,labels：

字段 当前格式
frame unit=source_dbu、正整数 dbu_per_uu、版本化 anchor_method
terminals ID → {name,direction,width,port?}；direction 为 input/output/inputOutput/unknown
anchors ID → {terminal,xy,escape}；同一 terminal 可记录多锚点，消费者另行限制
outline ID → 已登记 polyline/polygon/rectangle/ellipse/arc 图元
labels ID → {text,xy,bbox,kind}，kind 为 literal/dynamic_literal

symbol terminal 表是实际保存接口的观察，不是另一个人工修改 schematic 接口的入口。 有 schematic 时，port 映射须完整且名称/方向/位宽一致；独立 symbol 采集没有 topology 时， 必须有保存接口证据，并在 collection 说明。inputOutput 是现有枚举，不能写 inout。 未知方向可保留为事实，不能取得完整 Symbol 资格或当作可执行方向。 0.1.4 已把无 topology 的独立接口绑定到现有 source envelope：symbol.source 必须为 symbol_interface，symbol.depends_on 必须为 ["capture"]；sources.symbol_interface 必须是 kind=derived、method=saved-symbol-interface-v1、inputs=["capture"]，且 evidence_ref 等于 capture scope digest 与 terminal 名称/方向/位宽 JCS 摘要的组合。 新 qualification validator 使用 -symbol-interface-v1 后缀。旧 v3 回执保持原有 capture 依赖检查，不重分类、不提高已有包资格；缺少或伪造绑定只在新回执路径拒绝。

3. 坐标、单位与几何

  • 源坐标使用相对于 symbol 视图原点的整数 DBU，按实际采集的 dbu_per_uu 换算。 OA x 向右、y 向上；SVG 屏幕坐标转换由 renderer 负责，不能反过来改变源数据。
  • 当前 anchor_method 的已知值为 instance-min-or-view-origin-v1；未知值不能按视图 原点解释。施工首批已在 symbol_checks.py 强制核验该值，消除其与投影层的差异。
  • 目标 UU 坐标由 source_dbu / dbu_per_uu 再应用显式缩放和目标变换得到。 不假定 dbu_per_micron=1000；Symbol user unit 不自动等于物理版图微米。
  • pin anchor 必须落在目标连接网格上，terminal 的连接点与画出的 stub 一致。 主体曲线与 stub 的接触必须按真实图元校验，不能以 bbox 接触代替曲线接触。
  • 源几何、目标占用框与目标 selection box 分属不同对象；后两者从目标计划/回读派生， 不与源轮廓复制维护为多个可修改尺寸字段。
  • 当前 outline renderer 的 pin 网格为 0.0625 UU，每端口一条非零短线，长度不超过 5 × 0.0625 UU；字体/标签及供电位置沿用既有契约。它们是实现约束，不是任意 PDK 的普遍物理规则，也不能因本草案把它们降为“建议”。
  • B.9 的 symbol.json 保存 outline 图元和锚点，但不保存完整 pin figure、 lpp、线宽等 template_outline 当前需要的全部字段；因此“未登记图元”或 pin 图形差异只能按 raw/replay 证据定位，不能仅凭 symbol-reference-v1 推定 renderer 可重放。

下例为虚构的两端口矩形 Symbol 内容，用于解释 B.9，不是可发布模板或合格电路。 capture 来源与依赖、p_a/p_y 端口须由包内真实 sources/dependencies/topology 提供； 这里只有合法业务字段，没有伪造 passed 或专家签核。示例 dbu_per_uu=1000 仅为演示值。

JSON
{

  "depends_on": ["capture"],
  "frame": {

    "dbu_per_uu": 1000,

  },
  "terminals": {
    "t_a": {"name": "A", "direction": "input", "width": 1, "port": "p_a"},
    "t_y": {"name": "Y", "direction": "output", "width": 1, "port": "p_y"}
  },
  "anchors": {
    "a_a": {"terminal": "t_a", "xy": [-750, 0], "escape": "left"},
    "a_y": {"terminal": "t_y", "xy": [750, 0], "escape": "right"}
  },
  "outline": {
    "body": {"kind": "rectangle", "points": [[-500, -500], [500, 500]]},
    "stub_a": {"kind": "polyline", "points": [[-750, 0], [-500, 0]]},
    "stub_y": {"kind": "polyline", "points": [[500, 0], [750, 0]]}

4. 约束分层：按来源与用途判定

“硬/软/指导”只用于说明强制程度，不能由模型为字段随意分级，也不按电气/美观机械分类。 例如 +/- 既是视觉信息，也可能是极性语义；固定字体则可能是已确认交付要求。

类别 规则
接口与执行硬约束 目标完整端口、名称/方向/位宽/总线成员对应，明确 global/sigType 语义，保存前重验，既有 Symbol 不覆盖，task/request/digest 绑定
用户或实现已确定的图形硬约束 当前 power 上、ground 下；pin 网格与 stub 接触/长度；明确要求保留的主体与语义标记；失败须报告
可适配偏好 只有既有接口允许或本任务明确授权的缩放、非功能位置调整；不靠“更美观”越过硬边界
一般展示建议 未被固定的非语义留白/文字避让等；不得遮挡引脚、误导极性或执行源动态文本

特别约束：

  1. 极性/功能标记：运放正负号、反相泡、时钟边沿符号必须与相应 terminal 角色一致。 缺少角色证据时不能按名字猜测，也不能删除后仍声称忠实重绘。当前 renderer 不保留任意源 文字；如关键标记由文字承载，须先验证支持，必要时报告能力缺口。 0.1.5 的固定失败件为 gsclib045/INVX1 的源 Symbol [@info] 标签：旧的 template_outline 计划跳过该 label figure 并继续预览，未报告文字丢失。现在 outline_plan 在生成预览前核对源标签；只接受 cdsName()、[@partName]、 [@cellName]、[@instanceName]、terminal 名称和 cdsTerm("terminal")，其余 literal/dynamic 文字（包括 [@info]、cdsParam(...)、固定电压标注）抛出 TemplateUnavailable 并列出文本，不创建目标 Symbol。
  2. 供电与隐式连接：不得以高层框图或密集排版为由隐藏/删除电源 terminal、创建新继承连接 或改变 global/local。源 symbol 少画而 schematic 存在的端口由现有流程显式补出。
  3. 端口映射：已有 port_map 允许源到目标显式一对一改名，须保留方向、位宽、bus 顺序等； 不等于允许交换电气角色。net_scope_map 只能按已有明确规则使用。
  4. 位置与连接区分：移动 INP/INN 的几何位置不必然反相；交换 terminal 与网络对应才改变 电气语义。移动现有实例 pin 还会影响已连导线，所以不能以“无功能影响”跳过回读或覆盖保护。
  5. 可选电路组：omit/add 受 reuse 契约控制，不是一般软约束；Symbol 草案不扩大电路适配许可。

不新增每字段 constraint_tier、importance 与多个 allowed/prohibited 列表。若真实反例证明 现有格式无法保存必要的语义标记绑定，再向父标准提出最小扩展：一个权威字段/引用、一种 能力版本、未知特性的拒绝行为、迁移方式和反例验收。未登记前不通过 x_ 承载执行权限。

5. 当前可执行的消费流程

  1. 核对目标：读取已保存 schematic 的完整接口；检查同一 library/cell 的 symbol。 已有且一致则复用；不一致或检查失败时停止相关 TB 创建，不覆盖既有 symbol。
  2. 选择固定模板：检索用途许可及所需能力，读取接口/轮廓/缺口；区分 tpl_ legacy 与 ctpl_ 标准引用。源能力通过不免除当前消费者的支持范围和目标检查。当前创建还需 detail_level=raw 的 retained private capture；L1/L2/L3 投影只读参考，replay 拒绝 执行。施工首批由 make_plan → replay.require_symbol 在预览文件/原生调用前检查 standard_use.reference=allow；template_outline 另须 symbol-reference-v1=passed。 矩形样式不消费源 Symbol，不因该资产缺失而拒绝；两种样式继续逐项检查 schematic 完整接口及目标映射，不要求与 Symbol 无关的内部电路 topology/whole/core 资格。 当前仍需要 schematic 接口，独立 Symbol 的资格不会自动产生可创建能力。
  3. 选择已有样式：普通模块矩形使用 rectangular_module；保留门/自定义轮廓显式选 template_outline。默认值是矩形；不靠默认值宣称保留源轮廓，不支持时不得静默降级。
  4. 形成预览：复用已确认 task 呈现方式，传入必要的 port_map/net_scope_map/port_roles 和 outline_scale；检查预览中的完整端口、added_ports、缩放、主体/短线和标签。 outline_scale 仅在 template_outline 生效，允许 0.25..32；rectangular_module 会静默忽略它。port_roles 也只接受 template_outline，矩形模式传入会报错。
  5. 创建缺失 Symbol：用原 preview_ref/digest 和请求身份执行现有 create/draw 入口。 创建前重验目标；未知传输结果先查回执，不换请求 ID 绕过部分失败。
  6. 回读与显示验收：检查保存接口、几何、来源和原生实例显示；只有 schVIC/保存成功 不能宣称视觉通过。失败保留目标与证据供查询，不循环删除重建。
  7. 需要 TB 时：Symbol 通过后，使用同一 library/cell 的 symbol 实例作为 DUT。 不把内部 schematic 器件复制到 TB；缺少现有绑定能力时报告限制，不猜 pin 坐标。

辅助测试/probe 统一在当前工作区 SicoTest 后台通过 dbOpenCellViewByType 创建， 不打开、切换或抬升编辑窗口，不覆盖旧测试；库路径冲突须报告。用户交付目标及其 TB 才跟随 已确认呈现方式。若需连线，schCreateWire 第三个参数只允许 direct 或 full。 这些是现行工程约束，不要求为辅助测试重复询问用户。

6. 验收：分项结果，不以总分抵消错误

验收项 通过依据
数据格式 按 B.9 和包校验器解析；来源/ID/单位/缺口不矛盾
完整接口 对目标 schematic 检查端口、方向、位宽、bus 顺序与网络语义；无遗漏、重复或错误对应
几何连通 实际 pin/stub 接触、网格、长度及 selection box 回读符合所选 renderer
语义外观 极性/反相/边沿等含义保持；不存在误导标签或遗漏必要 terminal
持久结果 save/reopen/inspect 对应同一目标、模板与摘要；重复请求不产生第二份对象
原生可读性 在实际 Cadence 实例显示中检查遮挡、文字、供电位置与轮廓；截图绑定对象和源码/模板身份

交付通过要求全部适用硬约束通过且无阻塞缺口。 “未运行”记 unknown/not_run，不能记 passed； 原稿“硬约束违反率<1%”和总分≥0.7 的放行规则删除。

若后续评估要比较软偏好，只作为诊断量使用： S = sum(w_i × s_i) / sum(w_i)，w_i>0、0≤s_i≤1；无偏好时记 not_applicable。 例如两个偏好权重 0.9/0.8，只满足第一个，S=0.9/1.7≈0.529，不能再除一次 1.7。 硬约束失败立即不合格；S、人工视觉判断与硬结果分开报告，本稿不设未经校准的生产阈值。

8. 后续实施与发布条件
