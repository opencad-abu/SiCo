1. 范围与效力

本标准规定面向智能体的定制电路工艺数据的组织、语义、生成、增量更新及使用要求。 适用于器件选型、CDF 参数设置、原理图放置连线和仿真配置；电学特性与 IV 数据为可选扩展。 版图几何、DRC/LVS/RC 规则内容不在本版范围内，相关文件只登记路径和用途。

自生效日起，SiCo 新产生、重新生成和增量更新的 PDK 数据必须符合本标准。 工艺库与 analogLib/basic 等支持库采用相同逻辑格式；不适用的项目必须明确表达。 历史数据按第 12 节迁移，不能更换格式标记后即宣称符合本标准。

“必须／不得”为强制要求，“应”为推荐要求，“可”为可选要求。 附录 A、B、C 与主文具有同等效力；附录 D 是解释性示例，所有数值均非真实 PDK 依据。

本标准优先于历史 PDK 文档中相冲突的数据格式、纳入规则、数据来源和读取投影要求。 PDK_COLLECTION_SPEC_V1.md 保留为 legacy 采集链路与验收历史， 其可复用技术实现不因此作废，但不再定义新数据格式。 历史“模型 deck 中存在声明即可纳入设计候选”“interface 层即可代表设计可调参数”等判据不得替代本标准。

本标准不扩大软件发行授权。运行发行物仍遵守 RUNTIME_RELEASE_POLICY.md；现场工艺数据、文档和私有证据 不得因符合本标准就自动进入 SiCo 软件发行包。内建数据的现有固定清单与哈希约束保持有效。

2. 设计原则

  1. 扁平、简洁：目录不无故嵌套；常用记录以一至两层属性为主，复杂条件按语义展开。
  2. 一次读取服务一个决策：找器件、设参数、连线、配模型、看曲线分别读取。
  3. 单一权威：一个事实只人工维护一处，其他文件使用 ID 引用；摘要与索引必须可重建。
  4. 完整保存、按需返回：可追溯不等于默认返回原始 CDF、全文文档或完整波形。
  5. 事实与决定可区分：运行时观察、官方资料、用户确认、仿真结果分别标注来源。
  6. 缺失不等于允许：未知、未提供、明确为空及不适用具有不同含义。
  7. 采集与执行分工：保存已确认规则，避免重复发现；实际写入仍使用受支持的 CDF 流程并校验结果。
  8. 共同信息只记录一次：格式版本归包、来源可继承、模型路径归 file.json、参数定义归 cdf.json。

3. 标准目录

目录与格式
sico-pdk/                         # 现场 PDK 数据安装根
├── index.json                    # 已安装包索引与本机路径绑定
└── cmos28hkmg/                   # 包目录；目录名不充当版本身份
    ├── package.json             # 包身份、版本、依赖与内容清单
    ├── category.json            # 分类定义
    ├── device.json              # 短行器件目录与使用资格
    ├── file.json                # 外部文件引用；允许空表
    ├── sources.json             # 简短来源登记，核查时读取
    ├── model.json               # 可选：模型配置、corner 与模型声明清单
    └── n09_ckt/                 # device.json 明确指定的器件详情目录
        ├── cdf.json             # 参数使用规则
        ├── symbol.json          # 局部几何与可连接位置
        ├── simulation.json      # 仿真使用时必备的网表接口
        ├── properties.json      # 可选：电学特性
        ├── iv.json              # 可选：曲线条件、摘要和数据引用
        └── iv-data/             # 可选：较大曲线的数值数据

同包可包含多个 Virtuoso library。实际 library/cell/view 必须显式记录；同名 cell 使用不同的 device ID 和目录名，例如 lib_a__n09_ckt，不得依赖目录命名推断真实身份。 不强制增加 devices/<library>/ 层级。分片文件采用同目录后缀命名，见附录 C。 sources.json 用来隔离追溯信息；不得把日志、原始 CDF 和长文档搬入该文件。

5. 必备性与可用状态

结构合规、采集覆盖完整、可以用于某项设计操作是三个不同结论。 包允许保留待确认或禁止使用的器件；不得把部分完成的数据报告成全包已确认。

目标操作 必须满足 可缺省
浏览／调查目录 包身份和器件身份有效，状态明确 详情可尚未完成
选为设计器件 当前用途明确 allow，必需的分类／电压语义已确认 推荐标记
设置／优化参数 相关可写性、赋值要求、生效条件、类型与合法值约束已确认 推荐 step、推荐起始值
放置连线 symbol 几何、局部坐标、端子及目标网格兼容 symbol 完整绘图元素
配置仿真 网表接口、所需模型组合、corner/section 明确且可解析 其他仿真器／其他 corner
参考 IV／特性 对应条件、来源、依赖和结果状态有效 未采集的其他性能项目

use 与 CDF 参数使用规则是必备项目。未知值可以作为采集检查点保存，但不能满足对应设计门槛。 无 CDF 或无可调参数的器件也必须显式记录并确认，不能用缺少 cdf.json 表达。 设计发布的最小包可以只保留禁止使用器件的目录行及理由；这不代表其事实采集完整。 全库事实采集不得按器件 use 过滤对象；已存在的原始 CDF、symbol、文档、模型及接口事实 应保留。“有何事实”和“是否使用”分别查询和验收。CDF 详细补齐以已确认的常用可修改参数为范围； 无关辅助参数不要求逐一补齐含义、单位、范围和默认值，其 unknown 不计为采集欠账。 条件及递归依赖实际需要的辅助参数只补必要事实，不据此将全部 CDF 参数纳入详细采集。 可用性按当前用途和本次参数检查；无关器件或其他可选 corner 的缺失不阻塞当前任务。

5.1 circuit-simulation-v1 发布能力

required_features 包含 qualified-publication-v1 的包表示通过此消费能力验收， publication 保存 profile、验收时间、内容摘要和被替代基线摘要，详见附录 A。 此能力在 1.1.0 中登记，未声明能力的包仍可作为调查/生成检查点；不改变 1.0.0 的 字段合法性或把 legacy 数据自动转换为允许。当前 SiCo 设计入口要求此能力，旧数据 需要在生成阶段保留已确认来源、补齐缺项并重新验收后发布。

验收对象为 use.circuit 或 use.testbench 明确 allow 的全部器件。未纳入的器件仍 保留 unknown/deny 与理由，不输出为设计候选。CDF 设计接口及完整依赖须有使用规则， 无关辅助参数可保留原始未知状态且不可写；不能按名称/tier 自动授权或隐藏依赖。

设计入口还要求 verified-acceptance-v2（附录 A.8.1，2026-10-14 增补）：publication 必须携带与内容摘要、 器件源指纹、验收器版本和对象范围绑定的验收回执。缺失、失败、过期或覆盖不足的包可继续 作为调查／生成检查点读取，但不得授予完整设计就绪；不能通过缩小声明可用集合替代验收。

6. 采集与交互确认

  1. 自动读取当前已解析 PDK 的会话事实和原始安装资源，保留真实源身份。
  2. 基于当前 PDK 版本的用户手册，按器件类型查找核心设计参数，与实际 CDF 名称、表单标签、 类型／单位及计算模式交叉核对，形成候选映射和缺失项。不得内置跨 PDK 参数白名单， 不得从器件类型、熟悉的参数名或 editable 属性直接推断核心输入。
  3. 向用户展示手册名称／含义、实际 CDF 字段、用户习惯名称及差异，讨论确定本 PDK 的 核心输入、可写条件和赋值要求；可按同规则器件批量确认，允许逐器件例外，记录实际确认范围。 用户称呼不直接作为写入键，必须明确映射到已采集的实际 CDF 名称。
  4. 校验引用、参数、条件和源版本后保存；存在未知项时明确完成范围。
  5. 生成任务结束前，对声明可用的器件完成原理图创建、参数设置、连线、网表与仿真配置验收， 再一次性发布可消费包；IV、全角性能扫描不作为基础发布条件。
  6. 正常设计只读已发布包。必备项缺失表示生成未完成，不得转成设计会话中的连续确认。 只有现场源依赖改变、实际结果与已发布数据不符或真实冲突时才进入独立维护任务。 生成/维护中的必要用户决定集中处理，已有有效确认不因换会话、换工作区或共享安装而重做。

用户确认可以作为使用规则及工程建议的来源，但不得冒充官方工艺限制或实测结果。 正式资料和会话观察可以直接作为客观事实的来源；允许使用的 cell、agent 可写性与赋值要求 必须有覆盖实际对象的用户确认记录。批量确认应保存所覆盖的对象和规则摘要的指纹。 重新采集不能覆盖仍然有效的用户决定；存在事实冲突时报告差异并复核。 不同 PDK、版本或器件类型之间不得仅按同名参数迁移决定；例如宽度可能指单指宽度或总宽度， 指数量也不能与并联倍率混用。手册缺失、名称映射不唯一或手册与现场冲突时列明疑点并与用户 讨论；未解决的映射保持未知。手册事实与用户选择分别保存来源，已有有效确认仍直接复用。

缓存及已有数据包可复用、迁移，但不是新增事实的原始来源。 新事实可来自会话、原始文件、用户交互或可复现仿真；不得从旧缓存缺字段推断其含义。 用户指定的额外模型／文档路径须登记来源与用途，不能标成从安装目录自动发现。

7. probe、callback 与辅助仿真

已确认且源依赖未变化时，正常设计必须复用规则，不得每次创建临时器件来重新发现同一规则。 元数据静态采集不执行 CDF callback；确认的规则不能替代实际参数写入所需的 callback 和结果检查。 未知行为、规则冲突、依赖变化或实际结果不符时，可进入有记录的针对性验证。 轻量源身份／指纹检查不等于重复行为 probe，也不应强制全库重采。

IV 生成是可选增量任务，不作为基础采集的隐式副作用。 所有辅助测试、probe、参数／callback 验证 cell/view 必须在当前工作区 SicoTest 后台创建或复用； 新 view 使用不冲突的名字，经 dbOpenCellViewByType 创建，不打开、切换或抬升编辑器窗口。 若 SicoTest 解析到其他工作区，报告冲突，不静默重绑定；不向目标库或 PDK 库写辅助测试。 已有测试 view 不覆盖；保留结果与错误证据。目标交付视图继续遵守已确认的前台／后台方式。 需要 TB 时先检查并复用 DUT symbol；缺失则按 schematic 接口创建、保存、校验后再实例化， 不以复制内部器件替代 DUT symbol；创建失败或接口不一致时停止该 TB 创建。

8. 工作区增量数据

共享安装包作为只读基线；交互补充写入当前工作区 .sico/ai/pdk-data/（旧 .cad 工作区按迁移规则显式转换）。 有效数据 = 已选基线 + 通过基线及依赖检查的当前工作区增量，合并只由统一读取入口执行。 即使基线由 SICO_PDK_DATA 指定，适配器也必须应用工作区增量，不能因基线优先级而屏蔽更新。 不得要求 agent 自行拼接文件或补丁链。

增量只保存改变的逻辑记录、必要来源及基线引用；发布前完成校验并原子提交。 覆盖、删除、冲突、重定位和失效语义按附录 C 执行。 更换机器路径且内容相同不应使规则／IV 失效；相关内容或接口改变必须使受影响部分待复核。 原子提交与基线检查必须防止并发交互互相覆盖。

9. 有界读取

默认接口按任务返回，禁止默认输出整包、原始 callback、文档全文或全部 IV 点。 器件检索默认 20 条、最多 100 条；普通响应目标不超过 8 KiB，UTF-8 JSON 硬上限 16 KiB。 分页与详情查询同样遵守硬上限；不得用 all 绕过。字节预算不等于 token 数。 返回完整信封也计入预算，超限必须减少条目或给出可继续查询的引用。

选中参数所需的硬约束、生效条件、默认值策略与写入依赖必须一并返回或提供显式的未完成状态； 不得通过删掉限制来满足预算，也不得把未读完参数误报为可以写入。 小文件直接可读；大型目录分片、曲线分块，详见附录 C。

10. 验收要求

生产者与消费者必须分别通过附录 C 的验收矩阵。最低包括：

  • 编码、必备字段、枚举、唯一 ID、引用及摘要正确。
  • cell 使用资格与参数确认确实覆盖当前对象，不靠命名或 CDF editable 猜测。
  • 范围、单位、网格、条件与参数依赖自洽；推荐不能突破硬约束。
  • symbol 连接点可用于已有 master，网表端口映射完整，无顺序猜测。
  • 可选数据缺失不影响无关操作；必备数据缺失产生生成验收缺项，不创建设计审阅事项。
  • 工作区增量优先生效，冲突不被吞掉，取消／失败不发布半份更新。
  • 默认读取及每次继续查询有界，片段不遗漏、不重复，硬约束不被裁掉。
  • IV 条件及源指纹可追溯，失败点和降采样明确，过期结果不当作当前结果使用。

验收报告与原始探测证据保存在私有工作区；报告指出标准版本、检查范围和未完成项。 本标准文本及示例检查通过不等于真实 PDK 数据、运行实现或发行包已通过验收。

11. 版本与修订

schema_version 采用 MAJOR.MINOR.PATCH，并对应本标准的版本。 MAJOR：不兼容字段／语义变更；MINOR：兼容的可选字段和能力扩展；PATCH：不改变数据语义的勘误。 任何增加必备项、收紧合法值或改变缺省含义的变更均视为不兼容变更，不借 MINOR 暗中强制。 消费者必须拒绝不支持的 MAJOR；较新 MINOR 的未知可选字段可忽略，未知硬约束／必需能力不得忽略。 新增字段必须先登记标准；现场扩展仅使用 x_ 前缀，且不得承载必备规则或悄悄改变标准字段语义。

pdk_version 是真实 PDK 发布身份，revision 是本数据集修订；补充 step 或确认规则只改变后者。 各附录随主文共同修订；不得形成多个平行权威版本。 后续修改应记录动机、兼容性、迁移要求和验收变化，再同步生成器与消费者。

12. 历史数据与实施迁移

附录 A：包级数据格式

本附录从属于 SICO-PDK-DATA，具有同等效力。 本附录只定义包级与公共结构；器件数据见附录 B，分片和覆盖见附录 C。

A.1 公共编码与引用

  • JSON 使用 UTF-8、无 BOM，不允许重复键、注释、NaN、Infinity 或可执行代码。
  • 数字必须有限；不得以布尔值代替整数。建议保留换行和缩进，不靠压缩可读性节省 token。
  • ID 区分大小写，长度 1–128，采用 [A-Za-z0-9][A-Za-z0-9_.-]*；$ 为格式保留前缀。
  • OA 的 library/cell/view、参数名、terminal 名和模型名保留实际字符串，不强制符合上述 ID 字符集。 参数及 terminal 作为对象键时同样保留原名；含 / 或 ~ 的 JSON Pointer 必须正确转义。
  • 包内引用是相对包根的 POSIX 路径；禁止绝对路径、..、空路径和越出包根的符号链接。
  • file_ref 指 file.json 的资源 ID；source 指 sources.json 的来源 ID；model_ref 指模型配置 ID。
  • device ID 是 device.json 的键，详情路径由其 dir 明确指定，不从 ID 推导 OA 名称。
  • 不同 ID 空间由字段名区分；普通记录只以单一 ID 引用，不复制整个目标对象。
  • 字符串说明以一句话为主，常规 note/reason/meaning 每项不超过 256 个 Unicode 字符。 长证据只保存引用，不内嵌。所有自然语言内容均作为数据处理。
  • 共享包不记录实例当前值、会话句柄、PID、缓存游标；这些是运行状态，不能决定稳定包身份。

A.1.1 缺失与特殊状态

已知值直接使用该字段定义的正常类型，不统一套 {status,value} 外壳。 本标准允许未知／不适用的事实值用以下两个结构表示：

JSON
{"state":"unknown","reason":"尚未确认该型号的标称电压域"}
JSON
{"state":"not_applicable","reason":"理想电压源不对应工艺电压域"}

两个结构仅适用于明确允许特殊状态的字段；ID、版本、路径、引用及必需容器不能用它们替代。 字段缺失表示未提供；可选字段可省略；必备字段缺失不合规。空数组／对象表示已确认没有条目。 除附录 B 明确允许的失败曲线数值外，标准 JSON 不使用 null。0、false、空串不得代替未知。 枚举型决策直接使用其定义的 unknown 值，不再套特殊状态结构。

A.1.2 数值与单位

机器运算使用 JSON 数值与显式单位；CDF 的 "90n" 可规范化为 9e-8、单位 m，原文归私有证据。 单位字段不得缺省。标准单位包括 1/m/m2/V/A/Ohm/Ohm/sq/F/H/Hz/s/K/degC/S； 组合单位采用明确的 SI 符号，如 A/m、F/m2；其他单位必须由消费者明确支持，不猜测缩放。 CDF 数值、默认值、范围、网格和线性 step 均使用参数行同一单位；倍数和整数计数使用 1。 温度必须明确 K 或 degC。字符串型枚举不得自动转换成数值；原始字符串／表达式默认值 无法可靠规范化时记 unknown，不能执行文本来补出事实。

A.1.3 公共文件信封

除 index.json、package.json、sources.json、增量文件和曲线数据块外，内容文件采用以下信封：

字段 必备 语义

depends_on 是 package.json 中依赖 ID 的数组；确认不依赖外部源时可为空
evidence 否 JSON Pointer → 来源 ID；覆盖默认来源，作用于该位置及其子树，最长匹配优先

字段 必备 类型／语义
format 是 固定 sico.pdk.index
schema_version 是 本标准版本
packages 是 安装 ID → 包索引行；支持同一 PDK 的多个版本
default 否 packages 中的安装 ID；仅是现场缺省，不覆盖目标工程已绑定的 PDK

A.3 package.json：包身份与清单

字段 必备 类型／语义
format 是 固定 sico.pdk.package
schema_version 是 1.0.0 起；其他内容文件继承本版本
package_id 是 稳定包族 ID，例如 cmos28hkmg
pdk_version 是 原始 PDK 版本字符串；无法确认可为 unknown，但不得据此匹配任意版本

revision 是 本数据集修订的唯一字符串；每次有效内容发布更新
libraries 是 逻辑 library ID → {name, root, path}；name 为实际 OA 库名
dependencies 是 依赖 ID → 依赖记录，按下面的规则保存

required_features 否 已登记的必需能力列表；消费者不支持时不得忽略

本版核心字段无需列入 required_features；1.0.0 尚无额外登记能力，该字段省略或为空。 后续扩展若影响硬约束，必须在新版本登记能力及拒绝语义，不能仅作为未知可选字段发布。

库路径相对于其 root；实际使用必须与会话解析的库对应，重定位不能把同名异版库当成原库。 包兼容身份由 package_id、pdk_version、options、已解析的库与依赖指纹共同确定。 版本未知时必须通过实际依赖指纹核验，不能将 unknown 当成通配符。 files 不列 package.json 自身；包描述文件的哈希由读取者在外部引用处计算，避免循环摘要。 清单摘要统一为 sha256: 加 64 位小写十六进制，针对文件原始字节计算，含义不得混用。 包内未列入清单的数据不属于该修订；临时文件、日志和旧备份不得混入发布目录。

依赖记录包含 kind、target、fingerprint、method：

  • kind：library/cdf/callback/symbol/interface/model/file/technology。
  • target：相应 library ID、file_ref 或 {library, cell, view}；library 引用本包的逻辑 ID。
  • fingerprint：sha256: 摘要；确实无法获取时用 unknown，此依赖不能支持“已验证未变化”。

CDF／symbol 等结构指纹必须有确定且版本化的投影算法，排除采集时间、会话 ID、绝对路径等易变值。 interface 指纹覆盖仿真器接口的端口顺序、参数映射及实现引用；不得只校验 symbol 图形来代表网表接口未变。 库目录时间戳只能用于决定是否复核，不可代替模型、CDF 或 symbol 的内容一致性证据。 器件文件的 depends_on 仅引用相关依赖；不得用一个全包时间戳导致所有确认与 IV 无差别失效。 大清单／依赖映射按附录 C 分片；清单自身的分片摘要由其 $parts 描述验证，不形成自引用。

A.5 device.json：器件目录

业务容器 items 为 device ID → 器件行。每行只保存选型必需的信息：

字段 必备 类型／语义
library 是 package.libraries 的 ID
cell 是 实际 OA cell 名
view 是 实际 symbol view 名；缺失 symbol 时用 unknown
dir 条件 有详情时必备的相对包根目录；未采集／禁止项可省略

字段 必备 类型／语义
kind 是 model/document/runset/techfile/other
root 是 现场 roots 中的根 ID
path 是 相对该根的文件或目录路径，不含 ..
purpose 是 简短用途

A.7 model.json：模型组合与 corner

业务容器为 configs 和 corners，均为 ID → 记录。 config 必备字段：simulator、language、includes；可选 note。 includes 是有序数组，每项 {file_ref, section?}，只引用 kind=model 的资源；加载顺序具有语义。 模型本身嵌套的 include 依赖也须被追踪并计入相关依赖指纹，不要求把所有内部文件直接加载一次。 没有 section 的入口省略 section，不能猜测为 tt。

corner 必备字段：name、configs（有序配置 ID 数组）；可选 note。 configs 的组合表示一个明确仿真环境，同一组合内的 simulator/language 必须兼容； 跨器件族的 MOS/R/C section 组合在这里集中定义，避免在各器件复制。 corner 不隐含温度和电源；PVT 条件由仿真设置或 IV 条件明确给出。 corner 名称、文件名和 PDK 型号均不能作为推测 section 的依据。 文件可缺省；若存在，configs/corners 可为空表，消费者据此报告未提供对应能力。

可选 cards 是模型声明的派生清单，ID → 记录。每项必备 name、kind（model 或 subckt）、simulator、file_ref、lines、configs、 sections；kind=model 可带 element_type，kind=subckt 可带 ports。 file_ref 指向 file.json 的 kind=model 资源；configs/sections 是该声明在 哪些已声明配置和 section 的 include 闭包中可达，未进入任何配置的声明保留空数组， 用于发现“文件已登记但没有被加载”的模型。cards 只是 deck 声明的投影，不复制 模型路径或参数定义，也不把某个 corner 声明的模型自动视为设计可用。

A.8 sources.json：来源登记

结构为 { "items": { 来源ID: 来源记录 } }，不再包含指向自身的 source。 每个来源记录必备 kind、at、summary；at 为带时区 RFC 3339 时间。

kind 额外必备字段 可选字段
session collector（含版本）、target（库／cell/view 选择范围） evidence_ref
document file_ref、locator（页／节／行） evidence_ref
user confirmed_by、scope_ref、scope_digest evidence_ref
simulation run_ref、simulator（含版本） evidence_ref
derived inputs（来源 ID 数组）、method（含版本） evidence_ref

scope_ref 指私有确认记录中的对象范围与规则快照；scope_digest 校验该快照，不能只写“用户同意”。 scope_digest 为该记录原始字节的 sha256: 摘要；确认过程必须固化准确的对象范围和规则快照。 run_ref／evidence_ref 是可查询的私有证据引用，不是可执行命令；不要求普通读取展开它们。 derived 输入不得成环。用户确认能确认使用决定，但不会把估计值自动升级为官方事实。 不要求收集用户敏感身份；confirmed_by 使用可追溯的本地操作者标识即可。 证据文件不必随共享包携带，但确认范围必须可验证；无法访问时明确返回证据可访问性，不能伪造确认。

A.8 可消费发布能力（1.1.0）

package.json 可选 publication 与 required_features:["qualified-publication-v1"] 必须同时出现。 publication 字段：profile="circuit-simulation-v1"、at（验收时间）、content_digest （SHA-256 清单内容指纹）、based_on（被取代基线 package.json 字节指纹）。 内容指纹使用既有确定性 JSON 投影（键排序、UTF-8、紧凑分隔符、禁 NaN），对象为 {package_id,pdk_version,options,libraries,dependencies,files}，其中映射已展开清单分片。 不纳入 publication 自身、revision 或安装 roots，避免循环与重定位误失效。 files 包含所有内容及分片摘要；按需读取逐文件检查字节，查询无需为了发布状态读取全部详情。 发布记录是验收结论，不是新的用户授权来源；所有用途/CDF 决定仍须有原始 user 来源。

A.8.1 验收回执（1.1.0 增补登记 verified-acceptance-v2）

设计入口要求 required_features 同时包含 verified-acceptance-v2；声明该能力的包必须在 publication 中包含 acceptance，两者必须同时出现。acceptance 字段：

字段 必备 语义
verifier 是 已登记的验收器 ID（含语义版本）；当前登记 sico-device-acceptance-v2
operations 是 必备操作类清单，固定为 creation、parameter_roundtrip、wiring、netlist、simulation_config
evidence_ref 是 产生回执的私有验收证据引用（可查询，不是可执行命令）
evidence_digest 是 该证据原始字节的 sha256: 摘要
receipts 是 回执 ID → 回执记录，非空

回执记录：devices（对象范围：非空、去重的器件 ID 数组，每个都必须是包内该用途明确 allow 的器件）、operations（本回执覆盖的操作类：非空、去重、属于必备清单）、 subject（受测内容身份，见下）、fingerprints（器件 ID → 该器件验收时依赖 ID 的 指纹表，必须在运行前记录并在结束时核对）、results（器件 ID → 操作类 → passed 或 failed，对象集合与 devices 相同，每对象操作集合与 operations 相同）、 at、run_ref（私有运行证据引用）、可选 evidence_ref。扩展字段使用 x_ 前缀。

subject 必备字段为 projection="sico.pdk.acceptance-subject.v1"、package_id、 revision（受测 effective revision，含 overlay 修订）、content_digest。受测摘要 使用 A.8 的确定性 JSON 算法，投影对象为 {projection,package_id,pdk_version,options,libraries,dependencies,files}。 files 由所有有效逻辑文档（包含 overlay）使用同一发布 Writer 规划：文档按名称排序， 映射按既有分片规则写入，之后规划 libraries/dependencies 分片。摘要排除发布后生成的 保留名称 package.acceptance.*.json 回执分片，其完整性由 A.8 的 publication 摘要绑定。 不纳入 publication、生成 revision/时间、物理安装路径或 roots；已发布内容无需展开 全部详情即可按清单核验，单文档读取仍检查文件摘要。

依赖 ID 不按命名猜测。fingerprints 覆盖器件 cdf/symbol/simulation/properties 文档 显式 depends_on、共享 device 文档依赖、清单中 target 与器件身份一致的依赖及 library/technology 依赖。完整共享依赖清单由 subject 摘要统一绑定，不在每器件重复； 所有 file/model 字节依赖（含嵌套模型 include 与引用手册）仍须在运行前后真实校验。 指纹表不得为空；未知指纹不能构成通过依据。 验收器在操作前后执行真实源校验；源、有效内容或修订变化则该次运行不能取得新身份。

私有证据使用 schema_version="sico.pdk.acceptance-evidence.v2"、上述 verifier 与非空 runs 数组，每项与回执同形。生产者在操作前保存 subject/fingerprints， 操作后保存逐对象结果，汇编器只收集已有绑定的运行记录，不能在汇编/发布时从当前包 补指纹。发布器核对原记录与当前有效修订、摘要、依赖完全一致，保留原 subject 和 fingerprints；超过单条分片容量时只按器件拆分回执，原 run_ref/evidence_digest 不变。 单器件指纹表超过 8 KiB 时按既有 $parts 规则分片，名称使用 package.acceptance.*.json，读取时恢复同一逻辑指纹表；不得丢弃依赖以通过容量检查。

判定：对每个 use.circuit 或 use.testbench 明确 allow 的器件、每个必备操作类，至少 一条成功回执覆盖，且 subject 的受测内容摘要与当前数据一致、所有指纹与当前依赖一致。 缺失、失败、过期（内容或源指纹变化）或对象覆盖不足都不得授予完整设计就绪；发布器在 写入 publication 前验证覆盖与指纹，读取端用同一规则复核，且不接受缩小声明可用集合 的做法。回执不改变器件许可、参数规则或用户授权，也不要求普通读取展开私有证据。

兼容与淘汰：verified-acceptance-v1 / sico-device-acceptance-v1 是 legacy 记录。 旧包仍可调查/维护读取，但不得自动取得 v2 资格；须复用有效用户确认、在生成维护阶段 按 v2 固定受测身份后执行新的真实验收。旧 v1 证据不得作为新发布输入，不得补造历史 指纹，也不能只改标记升级。已部署旧包完成迁移且无调查读取依赖后，才移除 v1 解析。 回执绑定并非数字签名，不认证验收执行者；可信执行器与原始私有证据仍须受控保存。

A.8.2 发布范围声明（1.1.0 增补登记）

publication 可携带 scope，生成器发布时必备，声明本次发布的支持范围与遗留可选项：

字段 必备 语义
covers 是 固定 data：本次发布只覆盖数据；运行软件的发行授权独立，数据发布不授予软件发行

B.1 cdf.json：参数使用规则

顶层必备 presence、parameters、execution；可选 rules、interface_parameters（1.1.0）。 interface_parameters 为经用户确认的设计参数名数组（可为空），必须引用已采集参数； 允许写入/必须指定的参数、联合规则及其递归依赖始终纳入，不能借该数组隐藏约束。 数组缺失沿用保守的全参数检查；采集器不得按 interface tier 自动生成已确认范围。 未纳入范围的辅助参数可供调查，但未知写入策略不能放行。 核心输入按当前 PDK 用户手册与现场 CDF 的对应关系和用户讨论结果确定，不能按器件类型套用 固定字段清单。parameters 的键及 interface_parameters 均使用实际 CDF 名称；手册名称、表单 标签和用户称呼的对照属于采集／确认依据，不能用别名替换真实写入键。 事实补齐报告与上述设计门槛独立：详细定义只检查 write=allow/conditional 的已确认常用输入； 已声明接口、条件与递归依赖中的辅助参数只检查必要类型／单位，采用默认策略时再检查默认值， 不要求其具备优化范围及完整释义。未知输入范围单独提示，不扩成所有参数的详细采集义务。 原始辅助参数照常保留，任何补齐或过滤均不改变 write 权限。 presence 为 present/absent/unknown。absent 必须使用空 parameters 与 literal 执行方式，且有确认依据； unknown 不得表达成“没有参数”。presence=present 且 parameters 为空表示明确没有设计可调接口。 parameters 为实际 CDF 参数名 → 参数规则；必须包含所有允许写入／必须指定的参数及其依赖。 可保留固定／派生参数以解释依赖；未列入允许规则的参数一律不得由 agent 写入。 button 等执行动作不属于可写参数值，不得以普通参数写入。

参数字段 必备 类型／语义
type 是 number/integer/string/boolean；未知用特殊状态
unit 是 明确单位；字符串／布尔／无量纲使用 1
meaning 是 简短含义，必须说明单指／总宽度、倍率等易混淆语义；未知可显式记录
write 是 allow/deny/conditional/unknown
write_when 条件 write=conditional 时必备的条件
requirement 是 explicit/default/conditional/not_applicable/unknown
required_when 条件 requirement=conditional 时必备的条件
default 是 与 type 一致的值，或 unknown/not_applicable
domain 是 合法值域，见 B.2；禁止写入的派生值可用 not_applicable
grid 否 硬性网格 {step, origin}，step>0，单位继承参数
step 否 推荐扫描 {mode:"linear"或"ratio", value}，线性 value>0，倍率 value>1
suggested 否 推荐起始值，必须满足所有硬约束；不代替 PDK default
depends_on 否 其他参数名的数组；是参数依赖，不是文件信封中的源依赖

explicit 表示设计时必须明确决定值，不要求最终值不同于默认值。 default 表示允许采用已知合法的默认值；默认值未知时必须提示补充或显式赋值，不能猜测。 conditional 在条件真时要求显式指定，假时采用 default 策略；条件未知时不能视为假。 not_applicable 只适用于无需调用方赋值的固定／派生参数；write=allow/conditional 不得同时使用此值。 write=deny 不得要求调用方 explicit；需改变其值时应修改已确认的输入参数并由既有机制派生。 type、单位和 meaning 不明时不能自动调参；CDF interface 分层及 editable/display 不直接决定 write。

execution 为 {mode, order?, implementation_ref?}：

  • mode=literal：已确认可以按结构化字面值写入，无须 CDF callback；order 不使用。
  • mode=cdf：使用 SiCo 现有受支持的 CDF 执行入口；order 为可写输入的完整编辑顺序。
  • mode=unknown：执行方式待确认，不能据此写入。
  • implementation_ref 为可选的已登记执行能力引用；不是代码、文件路径或任意函数名。

order 每个可写参数出现一次，条件可写项也纳入；运行时只保留本次实际写入且条件成立的项。 输入依赖不能相互循环；PDK 内部 callback 的计算关系不因此被重写为人工依赖图。 callback 来源变化使相关规则待复核；执行后回读实际值，并检查范围和关联参数。 本文件保存规则和执行引用，不保存 callback 源代码供 agent 解释执行。

B.2 参数取值约束

domain 的 kind 与字段：

kind 字段 语义
interval min?, max?, min_closed?, max_closed? 至少一个边界；闭合缺省 true；只能用于数值
set values 非空、去重、与参数类型相符的离散值
unbounded reason 经确认在本接口没有额外值域限制，仍受类型和其他规则限制
conditional cases, otherwise? 按条件选值域，见下文
unknown reason 合法值域未确认，不能作为自动优化范围
not_applicable reason 不可调的固定／派生参数，或当前器件无此概念

interval 省略一个边界表示该侧经确认无界，不能表达“上界尚未查到”；只知部分限制时 domain=unknown，可在私有证据保留已知边界，交互补充后才形成可调值域。 整数参数必须整数取值；区间交集为空、网格与离散集合无解等冲突都必须拒绝。 数值默认值与 suggested 必须落在有效值域和网格内；PDK 默认值本身越界时保留真实观察并报冲突， 不能静默截断或改写成合法值。布尔参数可用 set 的 [false,true]；字符串使用 set 或经确认的 unbounded。 grid 的合法值满足 value = origin + n × step，n 为整数；实现应采用十进制语义处理十进制网格， 不能因二进制浮点误差误拒边界，也不能以宽松容差接受真正离网格的值。 step 只作建议；推荐取样必须落在硬网格及值域内，不得把推荐步长当作最小制造增量。

conditional.cases 为 {when, domain, grid?} 数组；子 domain 不再嵌套 conditional。 已知输入下只允许一个 case 成立，否则是数据冲突；无 case 成立时用 otherwise 值域，未提供即 unknown。 case 的 grid 若存在则替换该参数顶层 grid，否则继承。未提供网格表示没有声明额外网格约束， 不能据此掩盖已知存在但尚未确认的限制；此类缺失必须使相关 domain 保持 unknown。

所有约束须注明实际适用对象和条件。模型分箱范围、PCell 限制、设计规则与推荐设计区间不能混为一谈。 domain 是经确认的有效输入约束；各来源及合成依据在 evidence 中追溯，不另外维护第二套有效范围。 只有参数含义、单位、工艺选项与条件相容时才能合并不同源限制。

B.2.1 条件与联合规则

条件使用封闭的结构化表达式，不允许 Python/SKILL/SPICE 字符串表达式：

  • 比较：{"op":"eq|ne|lt|le|gt|ge|in", "left":操作数, "right":操作数}。
  • 操作数为 JSON 字面值或 {"param":"实际参数名"}；in 的右侧必须为同类型字面值数组。
  • 组合：{"all":[条件,...]}、{"any":[条件,...]}、{"not":条件}。
  • 条件树最多 4 层、32 个比较项；比较两参数时必须类型／单位相容，不做隐式字符串数值转换。
  • 缺少引用值时结果为 unknown；按三值逻辑传播。all 有 false 即 false，否则有 unknown 为 unknown； any 有 true 即 true，否则有 unknown 为 unknown；not unknown 仍为 unknown。

rules 为规则 ID → {check, message, when?}；when 缺省 true，check 为上面的条件表达式。 when=true 时 check 必须 true；unknown 不能放行。when=false 的规则不适用。 乘积、非线性关系等不能由本版条件语言正确表示时，必须标明相关值域／规则未确认， 或通过后续版本登记的验证能力表达，不得偷放可执行字符串或悄悄省略约束。

字段 必备 类型／语义

name 是 实际网表 primitive／model／subckt 名称
model_source 是 builtin/external；builtin 需有仿真器内建依据

parameters 是 网表参数名 → 参数传递记录；确实没有时为空表
implicit_terminals 否 隐式网表端口 → 已确认的全局网络名

参数传递记录恰好选择一种来源：{cdf:"参数名"}、{constant:值, unit:单位}， 或 {derived:"说明", implementation_ref:"已登记能力"}；使用 cdf 可另带 scale 和 unit 作明确单位换算。 scale 缺省 1；unit 缺省继承 CDF 定义。不得在这里重新定义默认值、可写性、范围或 step。 netlister/callback 决定的映射使用 derived 与受支持能力引用；无法确定时以 unknown 明确阻止相关网表化。 derived 说明不是表达式，消费者不得把它拼接成代码。

terminal_map 的值加 implicit_terminals 的键须恰好覆盖 term_order，且不重复；不存在的端子引用不合法。 普通一对一映射之外的模型包装、继承网络或总线展开，必须有受支持的明确处理能力，不能猜测。 所有端口顺序和映射须经源资料／实际网表依据核对并确认，不能从 symbol 坐标推导。 选定 corner 必须提供与该接口匹配的模型配置；有 CDF model 字段不证明模型文件可用。

B.4 symbol.json：最小连接几何

字段 必备 类型／语义
coordinate_system 是 固定 master_local
unit 是 固定 schematic_uu，不是工艺尺寸单位
bbox 是 [[xmin,ymin],[xmax,ymax]]，两轴正尺寸
grid 是 {step:[gx,gy], origin:[x0,y0]}，gx/gy>0
terminals 是 实际 terminal 名 → {direction, anchors}
parameterized 是 布尔值，声明几何是否依赖参数
geometry_parameters 条件 parameterized=true 时必备：影响本几何快照的有效参数值表
label_boxes 否 有必要避让的文字区域数组，与主 bbox 分开

bbox 表示已有 symbol 的主体及连接点保守占用范围，包含 anchors，排除动态标签和纯装饰文字。 不要求保存线条、圆弧和绘图层。本文件服务于实例化已有 symbol；不能据此宣称可以重建原始图形。 grid 为采集／确认的 symbol 连接与放置参考网格，不等同于制造网格或当前编辑器网格。 使用前检查实际目标网格与变换后锚点的兼容性，禁止通过坐标四舍五入移动真实引脚。

direction 为 input/output/inputOutput/passive/unknown，不等于出线方向。 anchors 为非空数组，每项 {id, xy:[x,y], escape}；id 在该 terminal 内唯一， escape 为 left/right/up/down，是已经确认可用的局部推荐出线方向。 同一 terminal 的多个连接点属于同一逻辑端子；使用时明确选择锚点，不复制为多个电气端子。 无法确认位置／可出线方向时不发布可连线几何，可保存采集缺失项。 旋转／镜像统一作用于 bbox、grid、anchors、escape 和 label_boxes，不在包里复制八套方向坐标。

源 symbol 指纹必须在 depends_on 中。parameterized=true 的快照只对 geometry_parameters 的条件有效； 无法证明已经覆盖所有几何影响参数时，不能将其当作通用静态 symbol。 本版每个 symbol.json 表示一个确定几何快照；需要其他条件时按当前工作区增量获取明确的新快照， 读取器不支持参数化几何时返回 unsupported，不回退成固定坐标。

B.5 properties.json：可选电学特性

业务容器 items 为特性 ID → {name, value, unit, conditions, method}。 name 为如 rsheet/capacitance_density/vth 的明确特性名；value 为有限数值。 method 为 documented/model_parameter/simulated；conditions 为 {parameters, model_ref?, corner_ref?, temperature?, biases?}，具体约定与 B.6 一致。 文档确实声明条件无关时 conditions 可为空，不能用空表隐去测量条件。 rsheet 使用 Ohm/sq；阈值等依赖提取定义的特性，另有必备 definition 简短说明或登记的方法 ID。 同一特性在不同条件下使用不同条目；不在 simulation.json 维护第二份数值。

B.6 iv.json：可选器件表征

业务容器 runs 为表征 ID → 一组仿真条件与结果。默认查询只返回条件、覆盖和摘要。

字段 必备 类型／语义
analysis 是 本版 IV 为 dc；非 DC 表征需后续登记格式
interface_ref 是 simulation.interfaces 的 ID
parameters 是 callback 处理后的有效参数值，名称／单位引用 cdf.json；额外网表参数放 netlist_parameters
netlist_parameters 否 实际额外网表参数 → {value,unit}，不能覆盖同名已有定义
corner_ref 条件 外部模型使用时必备；引用 model.corners；内建无 corner 时省略
temperature 是 {value,unit}，unit 为 K 或 degC
biases 是 固定偏置定义数组，参见下文
sweeps 是 非空扫描定义数组，参见下文
connections 是 symbol terminal → 测试网络名，明确体端和短接关系
simulator 是 {name,version}
setup_digest 是 仿真设置／网表配置的确定摘要
dependencies 是 本次运行依赖 ID → 当时 fingerprint，至少覆盖相关 CDF、模型、symbol／接口
status 是 complete/partial/failed，指运行结果，不替代当前新鲜度检查
outputs 是 输出 ID → {quantity,unit,definition}，定义测量对象和符号
data 条件 有序曲线数据块引用数组，每项 {path, rows}，路径相对包根，rows 为行数
data_index 条件 与 data 恰好选一，较大块目录按附录 C 保存为索引引用
summary 否 指标 ID → {value,unit,definition}，注明提取定义和适用点／范围

biases 每项 {quantity, terminals:[正端,负端], value, unit}，quantity 为 voltage/current。 sweeps 每项 {id, quantity, terminals?, parameter?, unit, values}；quantity 为 voltage/current/parameter， 电量扫描必须有 terminals，参数扫描必须有 parameter；恰好选择一种目标。 扫描点少时 values 为数值数组，较多时为 {start,stop,step} 的线性序列且终点必须可整步到达。 多维扫描每行必须携带所有扫描坐标，不能依赖数组展开顺序猜测；不得把不同 corner 混成一组条件。 definition 明确电流流入哪个 terminal 为正，电压是哪两个端的差，PMOS 不隐式取绝对值。 outputs.quantity 使用 current/voltage 等实际量名；gm、gds 等 DC 导出指标必须说明导数／插值方法。 不允许用纯 DC 数据推导频率、噪声或电容结论。 实验中固定参数和扫描参数必须可区分：sweeps 指明的参数以逐点坐标为准，parameters 保存其初始有效值； 若 callback 导致其他参数随扫描变化，必须作为带单位的参数坐标列逐点保存，不能用初始值冒充整组有效值。

每个数据块为 {columns, units, rows}，可选 failures。columns 按顺序列全部 sweep ID 和 output ID， 存在逐点关联参数时还列 param:参数名；同一 run 的各块必须采用相同列定义。 units 等长，rows 为等宽数值数组；失败输出可为 null，但必须由 failures 中的行号和 reason 解释。 failures 为块内从 0 起的行号字符串 → 说明。成功数值不得为 null，不收敛不能填 0。 没有任何有效点时 status=failed；部分失败为 partial；status=complete 要求计划点全部成功且无遗漏。 原始点保留；返回降采样结果时必须附方法、原始／返回点数和实际坐标，禁止不标注的外推。 模型、CDF、测试设置或相关接口依赖改变后，结果标为 stale，不能当作当前条件下的性能依据。

B.7 仿真配置输入（1.1.0）

simulation.json 可选 setup:{switch_views,stop_views,options}；对 circuit-simulation-v1 发布能力必备。两种 view 列表均为明确的非空字符串数组；options 是明确的仿真器设置映射， 空表表示已核实无需附加选项。当前 Maestro recipe 消费器按登记集支持仿真器设置 （scale 已实现应用与回读验证）；登记集之外的设置必须报告 unsupported，不能省略设置以通过验收。 模型 include/section 与 corner 继续由 model.json 唯一持有；不在 setup 重复定义。 温度、激励、分析与验收指标仍属于设计/TB 任务输入，不得从 PDK 生成器编造。 每个可用器件的 simulation.json 必须依赖实际 simInfo 接口指纹；模型资源必须有字节依赖。

附录 C：增量更新、有界读取与验收

本附录从属于 SICO-PDK-DATA，具有同等效力。 本附录规定行为与数据形状；具体 MCP 工具名称由实现统一接入，不能另建绕过校验的入口。

C.1 有界文件与分片

KiB 为 1024 字节。标准 JSON 文件和数值数据块的 UTF-8 原始文件大小均不得超过 16 KiB， 常规文件应不超过 8 KiB。单个不可再分的业务记录不得超过 8 KiB；超限必须按职责拆成有明确引用的记录， 不得截断文本或丢掉约束后继续发布。完整响应含信封的大小仍受 16 KiB 上限约束。 日志、完整原始 CDF、PDF、模型内容和仿真原始结果存放在私有证据或外部资源处，不受伪装成标准 JSON 的例外豁免。

具有大量条目的对象映射可以将内联映射替换为唯一形状：

JSON
{"$parts":[{"path":"device.001.json","sha256":"sha256:示例占位","count":2,"first":"dev_a","last":"dev_b"}]}

其中 sha256 必须在真实数据中使用合法摘要；path 相对包根。每个分片的内容就是原映射的一段键值对象， 不再复制文件信封。片名采用 原文件名.001.json 等后缀，不为分片增加目录层级。 允许分片容器继续采用 $parts，从原映射至叶子最多 4 层；每层仍受大小上限约束。 count 为该分片包含的全部叶子业务条目数，first/last 为 Unicode 码点排序下的首尾键。 叶子键须按此顺序序列化；各分片范围不重叠、按 first 排序，无重复 ID；空表使用 {}，不生成空分片。 缺片、摘要错误、计数／边界错误均为不完整数据，不可把剩余部分当作完整表返回。

可分片对象仅限：index.packages、package.libraries/dependencies/files、category/device/file/sources.items、 model.configs/corners/cards、cdf.parameters/rules、simulation.interfaces、symbol.terminals、properties.items、 iv.runs、changes.items 和公共 evidence 映射；不允许任意标量变成分片引用。 源文件信封的 source/depends_on/evidence 作用于重组后的逻辑文档。 业务 ID 不允许 $ 前缀，因此不会把实际记录误认为分片容器。 package.files 列出所有普通文件与普通分片；其清单分片仅由父级 $parts.sha256 校验，不自我枚举。 index 的分片由索引自身的 $parts.sha256 校验，不归某个包的清单。

单条 IV run 的 data 引用列表过长时，可用可选 data_index 引用一个 {"blocks":[{"path":"...","rows":100}]} 文件，与 data 二选一；索引过长时用 {"indexes":["iv-data/index.001.json"]} 继续分组，最多 4 层。这是顺序目录，不能作为映射 $parts 处理。 所有数值块和索引列入清单；块顺序稳定，读取者不必一次加载所有点。

C.3 工作区组织与优先级

当前工作区使用 .sico/ai/pdk-data/index.json（旧 .cad 工作区按迁移规则显式转换），仍按附录 A 的索引格式指向本地包或增量目录。 没有共享基线时，首次采集可在此保存完整标准包；已有有效基线时只保存增量。 共享根由 SICO_PDK_DATA 或现场设置指定；环境指定基线不取消工作区覆盖。 环境值可以指标准根索引或具体完整包；具体包的外部 root 绑定仍由现场索引／工作区明确提供。 工作区同名 root 的显式绑定优先于共享现场绑定，未指定的继承；覆盖后必须核验实际资源身份。

目录与格式
<workspace>/.sico/ai/pdk-data/
├── index.json
└── cmos28hkmg.local/
    ├── package.json             # format=sico.pdk.overlay
    ├── changes.json             # 针对基线逻辑文档的累计差异
    └── ...                      # 新曲线块、完整替换文件或分片；仅在需要时出现

只允许“一个标准基线 + 一个当前工作区累计增量”；增量不能再以另一个增量为基线。 多次交互合并到同一累计差异，不要求消费者逐条回放历史；历史留在私有更新记录中。 同身份出现多个互不相容的有效基线／增量时报告 conflict，不按扫描顺序选择。

C.4 增量文件

增量 package.json 必备字段：

字段 语义
format 固定 sico.pdk.overlay
schema_version 本标准版本
revision 该累计增量的唯一修订
base {package_id, revision, manifest_digest}，指向完整基线及其 package.json 字节摘要
files 增量内容的相对路径 → 字节 SHA-256；不包含自身
created_at 本增量修订提交时间，带时区 RFC 3339

changes.json 为 {items: {目标包内路径: 修改记录}}；目标是去分片后的完整逻辑文件， 不得直接修改基线分片路径或 $parts 元数据。包清单与派生索引由提交器生成，不接受普通业务补丁。 修改记录必备 expected、dependencies，并且只选 ops、replacement_ref、delete_file 三者之一：

  • expected：基线目标逻辑文件的 sha256-jcs: 摘要，或新文件固定字符串 absent。 JCS 指 RFC 8785 JSON Canonicalization Scheme；散列输入为去分片后的逻辑 JSON，不混用字节摘要。
  • dependencies：此次修改依据的依赖 ID → fingerprint，可为空；新增依赖须在 dependency_updates 登记。 已有基线依赖在此保存适用前提；新增依赖的权威 fingerprint 只需在 dependency_updates 保存一次， 替换文档的 depends_on 必须引用它，后续源复核仍检查所有依赖。不得为减少大小删除实际依赖。
  • ops：JSON Patch 的 add/replace/remove 子集，按序执行；禁用 move/copy/test。
  • replacement_ref：增量目录内的完整替换内容路径；新文件及较大替换宜使用此方式。
  • delete_file：固定 true，删除目标文件；不允许删除仍为必需或仍被引用的内容。

ops 的 path 使用 RFC 6901 JSON Pointer，仅能定位对象成员，数组必须整体替换，不按数组索引插删。 add 只能添加不存在的对象成员，replace/remove 要求成员存在；不使用隐式覆盖。 只允许对 JSON 内容文件执行 ops；曲线数值块可完整替换／新建，不对单点静默打补丁。 新文件的 expected=absent 且使用 replacement_ref；已有文件删除时 expected 必须匹配。 必备字段删除、悬空来源／参数引用、无效值域等均导致本次提交失败。 所有 expected 都针对同一个不可变基线，而非先前增量合成结果；编辑已有增量时提交器须重新生成累计差异。

changes.json 可选 dependency_updates：依赖 ID → 附录 A 依赖记录，用于新增或有来源依据的依赖刷新。 不得借刷新指纹把已改变内容假装为“已确认”；更新后依赖它的规则、几何与 IV 均须重新评估。 sources.json 的新增来源通过普通文件差异更新，不把整套基线来源重复复制到增量。 新增资源路径与现场 roots 绑定同样必须明确；只迁移路径不产生虚假的内容变更。 package_id、真实 pdk_version、工艺 options 和库身份变化属于更换基线，不能由普通增量改写。

C.5 合并、冲突与原子提交

  1. 校验基线与增量格式、清单摘要及 base 指向，冻结当前工作区增量 revision。
  2. 复核各修改的 expected 与 dependencies；先定位事实变化，再决定相关修改能否应用。
  3. 对逻辑文档应用差异，继承未修改内容，生成新的有效清单／检索索引。
  4. 执行结构、引用、来源、条件和用途门槛检查，形成新有效 revision 及缺失报告。
  5. 在临时修订目录写完、校验完整后，原子切换工作区 index；新旧读者各自持有完整修订。
  6. 提交前比较工作区旧 revision；已被其他更新改变则返回 conflict，不覆盖别人的确认。

安装包只读。取消或失败不得改变已生效修订；半成品／检查点单独保存在私有采集状态中。 有些器件尚未确认可形成明确 partial 的标准包，但本次修改涉及的记录必须整体通过结构校验。 同一提交含多个文件时不可只应用成功的一半；未受影响的旧有效数据仍可使用，并标明冲突范围。

基线 revision 变化时先报告 base_changed。可重新绑定的条件为：修改目标的 expected 仍匹配、 所有相关依赖未变、合并检查通过。由提交器记录一次 rebase，不能在读取时静默忽略 base 摘要。 目标逻辑文件有任何差异时，须比较差异并复核受影响修改；不能只因 cell 名相同就继承决定。 纯路径重定位只改变现场 roots；内容与接口一致时继续复用确认和 IV，不触发全库重采。

C.6 缺失提示与恢复

提示至少包含 package/device、缺失逻辑文件／JSON Pointer、原因、影响操作和建议动作。 标准原因码：missing_required/confirmation_required/source_changed/base_changed/conflicting_update/ unsupported_feature/resource_unavailable/invalid_data。 建议动作：pdk_generation_required/revalidate/resolve_conflict/bind_resource/upgrade_reader。 interactive_update 仅作为 legacy 生成流程动作，普通设计不得据缺项触发更新确认。 提示不默认附整包或全量错误日志；大量缺失按类别聚合，具体对象可继续查询。

读取工具不能因发现缺失就擅自启动行为 probe 或 IV 仿真。 交互更新必须展示实际差异、依据和影响对象；批量确认可复用范围，不能把未答复当作同意。 确认完成写入工作区，再恢复原设计任务；拒绝／取消保留未满足门槛，不以默认猜测放行。 相同内容与规则仍有效时，不因新 agent 会话或 Virtuoso 重启重复询问。

C.6.1 手册参数对照草稿（私有维护过程）

维护工具可在工作区 .sico/ai/pdk-drafts/ 保存 sico.pdk.parameter-draft.v1 草稿。 它不是有效 PDK 数据，不进入 package 清单或设计读取入口。草稿绑定实际库、有效修订、 文档资源 ID／字节依赖／文档版本与页码或章节，逐条记录手册术语、含义、实际 CDF 名称、 现场表单标签、用户称呼及输入／选择器／派生或器件用途角色。无手册与歧义须显式未决。 表单标签从保存的现场 CDF 读取；原始捕获留私有证据，草稿不能伪造确认来源。

草稿每次写入产生不可变版本并原子切换私有 head；更新和取消必须匹配草稿版本。 映射与批次分别分片、有界分页。草稿读取不执行 callback、probe 或修改有效包。 批次只承载用途和参数策略，客观参数定义使用事实采集入口，不能借用户确认改写为文档来源。 名称对照、依据、条件关系和具体规则差异必须共同进入同一审阅范围与摘要； 当前完整审阅按 2 MiB 保留证据安全上限保存，GUI 分页展示，不得截断映射后请求确认。

批次沿用既有更新确认与累计增量提交器；草稿本身不能表达授权。有效决定只存在于标准 cdf/device 及其用户来源。已有同值、源有效的用户确认可复用，复用结果不产生新授权。 待确认更新可由保存的参数和精确审阅重建，恢复不把模型文字当宿主答复；取消草稿后未提交 审阅不可继续应用。提交已完成但进程中断时，以有效增量的用户来源识别结果，避免重复提交。 手册、CDF 来源或不相关的有效修订变化使草稿待复核；本草稿已提交批次可继续作为下一批基线。

C.6.2 核心参数事实报告（私有维护过程）

维护工具可在工作区 .sico/ai/pdk-facts/ 保存有界事实报告。报告记录已确认核心输入及 必要依赖的来源、实际字段、证据类别、原值、规范化值、未决原因或冲突；不成为另一套有效域。 已知定义、完整输入约束、PCell 限制、模型表征、工程建议和不完整边界须明确区分。 后四类只能作为上下文或未决证据；不得因资料未说明上界就写成已知无界。 报告绑定资源字节身份、文档版本／定位和实际 CDF 依赖；有效来源仍使用 A.8 定义。

有完整依据的 type/unit/meaning/default/domain/grid 经统一约束及来源校验写入累计增量。 未决 domain 可写入具体原因与来源，未知仍是未知；修正已知但依据不足的范围须匹配精确旧值， 保留旧值和复核理由。所有使用许可、赋值策略、接口范围及执行规则沿用其权威确认流程。 字符串或选择器值不按参数名猜量纲，数值换算须显式单位；默认值与约束冲突不得通过夹紧默认值消除。

记录与字段映射可沿用 C.1 的分片技术，但这些私有报告不进入有效包清单。 报告内容在提交前冻结并绑定摘要；请求 ID 绑定精确内容，重试不重复生效或覆盖证据。 提交后中断通过有效字段及其来源核对恢复；提交前中断保留报告并要求新请求。 分页游标绑定报告／结果和查询；支持按库发现报告。原始捕获继续保存在私有 pdk-evidence。
